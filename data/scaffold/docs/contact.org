* Default: no submission
This scaffold defines a contract, not a working endpoint. Do not add a form when the brief excludes one. Without an explicitly configured service and recipient, omit submission controls and explain that messaging is unavailable. Never invent an address, send personal data via GET, or report a successful send without a successful response.

* Request
A future same-origin endpoint accepts POST /contact with application/x-www-form-urlencoded fields: name (trimmed, 1..100 Unicode characters), email (required, at most 254 characters, validated by the backend), and message (trimmed, 1..5000 Unicode characters). Limit the encoded request body to 64 KiB. Reject duplicate or unexpected fields, except the framework's documented CSRF token field. Never put submitted values into email headers without injection-safe handling. The endpoint and delivery adapter must be configured and documented before enabling the form.

* Response and state
For ordinary HTML submission, accepted delivery or durable queuing redirects with 303 to a confirmation page. A documented JSON enhancement may request application/json and receive 202 with status "accepted"; this means accepted for processing, not delivered. Return 400 for invalid fields, 403 for failed origin/CSRF validation, 413 for excessive size, 429 with Retry-After for rate limits, and 503 for unavailable delivery. Never acknowledge success before delivery or durable acceptance. Preserve input and provide retry guidance after failure; do not log message bodies or leak backend errors.

* Accessibility and verification
Use native labels, autocomplete=name/email, a textarea, an error summary linked to fields, aria-describedby for errors, and a polite status region. Keep the ordinary POST workflow working without JavaScript. Associate validation with the affected field and prevent repeated submissions while pending. Server validation is authoritative. Test valid/invalid input, Unicode and whitespace, oversized/duplicate fields, CSRF, rate limiting, backend failure, repeat submissions and keyboard/no-JavaScript behavior. For loopback servers allow both localhost and 127.0.0.1 on the configured port while enforcing origin and CSRF rules. Document actual retention, delivery provider and abuse controls in the reviewed privacy policy before enabling collection.
