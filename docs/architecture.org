The function-by-function embedder catalog is [[file:api.org][api.org]]. This page is the lifecycle, ownership, signals and extension contract.

* Components

| Directory | Responsibility |
|-----------+----------------|
| src/core | Recipe validation, prompt catalog, artifact context, pipeline and published-tree QA |
| src/interfaces | LsProvider transport interface |
| src/model | Immutable boxed LsArtifact |
| src/providers | ai-glib CLI transport adapter |

The public umbrella header is =libresite.h=. The build emits a static archive, a shared library with SONAME =liblibresite-1.0.so.0=, a CLI and =libresite-1.0.pc=. This is a new 0.1 API; reserved vtable slots leave room for additions, but callers should pin compatible releases. Public error domain =LS_ERROR= uses =LS_ERROR_INVALID=, =LS_ERROR_CONFLICT=, =LS_ERROR_PROVIDER= and =LS_ERROR_LIMIT=. =LS_MAX_DOCUMENT= (16 MiB) and =LS_MAX_PROJECT= (64 MiB) are the public size macros.

* Lifecycle

=LsRecipe= parses and validates YAML before output creation. =LsPipeline= resolves registered types and catalog names before any provider call. Each generation step builds a fresh merged settings object and sends a focused project payload plus the stage contract to =LsProvider=. The payload always includes a path/size/encoding/SHA-256 manifest. UTF-8 contents are inlined for the whole project unless the step names =options.files= or =options.context=, in which case only those paths plus contract documents are inlined. Binary files stay in the manifest unless =context= names them. A complete provider bundle is applied transactionally to =LsContext=. A durable checkpoint is written before the step is considered complete. After every step succeeds, the context is exported into a fresh directory within the private workspace, metadata is added, and a same-filesystem GFile move publishes the output without replacing an existing destination.

=ls_recipe_set_timeout()= supplies an execution-only deadline override before a run; merged settings reflect it but the parsed recipe tree stays immutable. =ls_recipe_set_unlimited()= additionally disables requested output budgets and takes precedence over a finite timeout override. Both provider configuration and rendered =AI SETTINGS= use the same merged values. This lets =--timeout= and =--unlimited= recover an existing checkpoint without changing the intended project or catalog.

The checkpoint is the source of truth on resume. Partially exported directories do not become input, and failed model output is never reused. Matching fingerprints bind the parsed recipe, prompt catalog and checkpoint format. The fingerprint detects configuration drift, not a malicious user who can rewrite the checkpoint. Workspace ownership/mode checks and an advisory exclusive lock protect normal concurrent use.

=ls_package_save()= archives the original immutable recipe and catalog text plus a strict versioned YAML manifest carrying their SHA-256 digests and SKU metadata. Recipes selecting native scaffolding also archive its exact file bundle with a separate digest. =ls_package_load()= checks all pins and returns an owned recipe/catalog pair only after complete validation. The recipe carries an optional immutable native snapshot alongside its original text; scaffold execution and CLI preview filter that snapshot against existing seed paths, while the pipeline fingerprints the exact archived bytes. CLI sealing preflights module and prompt compatibility before publication; library callers do the same with their configured pipeline. Archives move independently of source paths and do not depend on later embedded catalogs or native templates. Execution overrides are excluded. This adds durable input retention without changing the existing fingerprint formula or checkpoint format; see [[file:packages.org][sold packages and compatibility limits]].

Before publication, the pipeline extends or creates the exported =.gitignore=, initializes a standalone repository on =master=, stages nonignored files and creates =chore: initial generated project=. This is deterministic publication behavior for every provider and native plugin, independent of model compliance. These export-time additions do not mutate the artifact context or checkpoint; artifact signals continue describing model/plugin artifacts. Git commands use an isolated Git environment with system/global configuration, template hooks, signing and inherited repository pointers disabled. The initial identity is supplied per command, not persisted in user configuration. Cancellation terminates and reaps the active Git child before returning. A Git error leaves the checkpoint intact and the requested output absent.

Optional recipe =seed_artifacts= are validated transactionally during parsing and copied into a fresh =LsContext= through =ls_recipe_create_context()=. Preflight and CLI previews use that same initial context. Fresh runs save it in checkpoint zero before executing any module. Resume restores the checkpoint without reseeding, so accepted replacements survive. Inline seed content belongs to the parsed recipe fingerprint; recipes without seeds retain their previous identity.

* GLib ownership and threading

=LsRecipe= and =LsPrompts= own their parsed JSON trees. Accessors return borrowed data; do not mutate it. =LsPipeline= references its provider and prompt catalog. =LsContext= owns its artifacts, and =ls_context_lookup()= returns a borrowed immutable artifact. =LsArtifact= is a boxed value with a deep copy operation; strings returned from its accessors live as long as the artifact. All owning public types support automatic scope cleanup.

Pipeline operations are synchronous and intended for a worker thread. Do not call a pipeline concurrently or reenter it from a callback; an active-run guard rejects reentry. Its signals run on the calling thread. The CLI uses one worker plus the default main context for SIGINT/SIGTERM delivery; applications must marshal UI updates to their own UI context. Custom providers and steps must honor =GCancellable= and return a useful =GError=. They must not return success while setting an error.

* Signals

| Signal | Arguments | Timing |
|--------+-----------+--------|
| step-started | id string, index unsigned | Before step execution |
| step-completed | id string, index unsigned | After durable checkpoint write |
| step-progress | id string, index unsigned, message string | Attempt settings and retry reasons, forwarded from LsStep::progress |
| artifact-written | LsArtifact boxed value | After successful directory publication, once per final artifact |
| completed | output path string | After successful directory publication |

Indices are zero-based. Resume emits signals only for steps actually run. The callback arguments are borrowed; copy an artifact or duplicate strings to retain them. Failures return through =GError= rather than a second competing completion channel. The CLI prints progress and errors to stderr.

=LsStep::progress= carries a borrowed human-readable message on the executing thread. Custom steps can emit it to describe work without implying artifact acceptance. The pipeline connects it only during execution and forwards it as =step-progress=. The CLI copies the current status under a mutex for its main-context 30-second heartbeat; its timer and signal handlers are removed after the worker joins.

=LsProvider::usage= fires after each dispatched =ls_provider_generate()= with borrowed provider, model, input-byte and output-byte values. Steps collect it into =ls_step_dup_usage()=. Calls that bypass the wrapper are not counted. See [[file:usage.org][usage.org]].

* Implement a new module

Subclass =LsStep=, override =LsStepClass.execute= and register the concrete type with =ls_pipeline_register()=. A registered type must support construction with no required arguments. Store per-run state on the instance, read configuration from =config=, and publish files through =ls_context_apply()=. Register before starting a run. Duplicate names and abstract types are errors. The registry belongs to one pipeline and has no global registration order.

The execute vfunc receives the parsed recipe, step options, prompt catalog, current artifact context, transport, cancellable and error location. This supports modules for frontend frameworks, database migrations, backend scaffolds, source validation, asset transforms or deterministic templates. A new generative specialization can simply register =LS_TYPE_GENERATE_STEP= under another name and select an existing =prompt= key; add its dedicated contract to the YAML catalog when it needs different instructions.

For a CLI-loadable module export this function:

#+begin_src c
#include <libresite.h>
#include <gmodule.h>

G_MODULE_EXPORT gboolean ls_plugin_register(LsPipeline *pipeline, GError **error);

/**
 * ls_plugin_register:
 * @pipeline: host pipeline
 * @error: return location for an error
 * Returns: whether registration succeeded
 */
gboolean
ls_plugin_register(
	LsPipeline *pipeline,
	GError **error
){
	/* Reuse the built-in generator with prompt: generate in the recipe. */
	return ls_pipeline_register(pipeline, "catalog-page", LS_TYPE_GENERATE_STEP, error);
}
#+end_src

#+begin_src bash
gcc -std=gnu89 -Wall -Wextra -Werror -fPIC -shared catalog-plugin.c \
    -o catalog-plugin.so $(pkg-config --cflags --libs libresite-1.0 gmodule-2.0)
libresite --plugin ./catalog-plugin.so -r catalog.yaml -o ./catalog-site
#+end_src

Plugins are explicitly selected native code and run with the caller's privileges. The CLI keeps them resident because registered GTypes outlive registration. This is a C ABI extension boundary, not an untrusted plugin sandbox. Plugin options, external resources and plugin version compatibility must be managed by the plugin; changing plugin code is not detected by the built-in recipe/catalog fingerprint. Use a new output path after changing a plugin.

[[file:../tests/fixture-plugin.c][The external fixture plugin]] is a complete non-AI subclass example compiled against installed public headers by the install test. It demonstrates artifact generation independently of the transport.

* Implement another provider

Implement =LsProviderInterface.generate=. Return an owned UTF-8 JSON file-bundle string or NULL with an error. The interface receives merged settings and separate system/task prompts. The pipeline is independent of ai-glib beyond =LsAiProvider=; a test transport, local model server or another API implementation can be injected without changing recipe, checkpoint or artifact code. The current CLI selects =LsAiProvider=; applications embedding the library may inject any provider object.

Configure =ls_ai_provider_set_debug()= before generation to opt into provider-native session persistence and metadata diagnostics. The CLI exposes this as =--debug=; it is transport configuration rather than recipe state and does not affect checkpoint fingerprints. Do not change the setting concurrently with a provider call.

* Dependency roles

=ai-glib= implements CLI protocol details. =yaml-glib= provides YAML document conversion, with libyaml used for stricter syntax validation before conversion. GLib/GObject/GIO provide ownership, signals, filesystem operations, subprocess cancellation integration and CLI parsing; JSON-GLib represents validated recipes and exact file bundles. =htmx-glib= and =orm-glib= remain pinned dependencies for generated GLib web/persistence integrations, rather than mandatory links in the builder: generating a static site does not require a web server or database runtime inside libresite. =site.stack= selects a catalog string in =stacks=; =c-glib= supplies the pinned API/build context for generated applications. Profile resolution belongs to =LsPrompts= and preflight, with no framework-specific orchestration branches or runtime dependency discovery. Custom catalogs can add stacks without modifying the pipeline.

* Defensive extension and validation boundaries

The provider and step dispatch wrappers capture a private =GError= even when callers pass =NULL=. Success accompanied by an error is rejected; failure without an error receives a diagnostic. Cancellation after a callback takes precedence and is normalized to =G_IO_ERROR_CANCELLED=. This prevents broken extensions from reporting accepted output or completed steps. A native plugin is still trusted code: arbitrary in-memory mutations and external side effects cannot be rolled back by the dispatch wrapper.

=ls_validate_step_check_options()= is the public, non-mutating schema validator shared by preflight and execution. It checks required paths and optional exact-content/byte predicates without a transport call. Generation uses the same validator against isolated candidates before accepting downstream contracts. See [[file:recipe-format.org][the recipe reference]] for predicate semantics.

JSON parsing enables JSON-GLib strict mode and rejects rootless input, comments, JavaScript assignments and trailing commas in addition to duplicate keys, NUL and nesting limits. Schema keys containing the internal allowlist delimiter are rejected rather than matching multiple adjacent allowed names. The builder requires JSON-GLib 1.10 or newer for strict parsing.

CLI plugin registration follows the same result/error rule. A failing registration aborts preflight, including success paired with an error; resident modules stay loaded because they may already have registered GTypes. Install tests compile malformed registration callbacks against the installed headers to verify both failure forms.

* Revision lifecycle

=ls_pipeline_revise()= imports an existing source into a revision context before creating its output workspace. =ls_pipeline_validate_context()= validates prompts against imported files. The source snapshot and executable intent join the recipe/catalog checkpoint fingerprint; =ls_context_restore()= replaces the full checkpoint state instead of merging it into source files. =ls_context_apply()= accepts transactional =delete= and =rename= operations, optional file =executable= booleans and optional =encoding: base64= for binary artifacts. =LsArtifact= remains immutable, with =ls_artifact_new_bytes()=, =ls_artifact_is_binary()= and =ls_artifact_get_executable()= exposing storage intent. Native =gate= steps stop before implementation until =ls_recipe_approve()=; =ls_qa_check()= inspects a published tree without executing generated code. Publication creates a fresh standalone repository, preserving the source. See [[file:revision.org][revision.org]] for source limits, exclusions, prompt scope and recovery.

* Usage accounting

Step execution records and explicit rate-card pricing are described in [[file:usage.org][usage.org]]. Checkpoints and run metadata include =usage= and =usage_complete=. An in-flight marker prevents pricing a history with a crash gap. Failed executions persist their usage alongside the previous accepted artifacts. Legacy checkpoints remain resumable but are not priceable.
* Native scaffold
=LsScaffoldStep= emits embedded static templates through the normal atomic context boundary, never the provider. Bundled static workflows run it first. Existing paths survive, template bytes participate in checkpoint identity, and CLI previews apply preceding scaffold steps in memory. Embedders can call =ls_scaffold_step_render()= or =ls_scaffold_step_render_recipe()= and then =ls_context_apply()=. See [[file:scaffold.org][native scaffold contracts and verification]].
