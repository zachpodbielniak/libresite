* Three-file build

=config.mk= defines compiler flags, packages, output directories and feature switches. =rules.mk= implements compilation, generated resources, header dependency tracking and build-flag stamps. =Makefile= declares the library, CLI, tests and installation. This follows the reference ai-glib/clawtilla organization rather than introducing another build system. =make clean all tests -j4= serializes cleaning before building to avoid removing objects during parallel compilation.

=CC=gcc= and =-std=gnu89= are the supported compiler/language combination. Project code builds with =-Wall -Wextra -Werror -Wformat=2 -Wshadow -Wstrict-prototypes -Wmissing-prototypes -Wdeclaration-after-statement=. No warning category is disabled. =-MMD -MP= tracks header dependencies. Changes in compiler, flags, sanitizers or installation prefixes update a stamp and rebuild affected artifacts. Embedded prompts and the existing license are generated by =glib-compile-resources=.

* Packages and dependency modes

Fedora builder packages: =gcc=, =make=, =pkgconf-pkg-config=, =glib2-devel=, =json-glib-devel=, =libsoup3-devel= and =libyaml-devel=. =DEPS=system= optionally uses compatible installed =ai-glib-1.0= and =yaml-glib-1.0= development builds. Those are the user's own libraries, not assumed Fedora distribution packages. Their pkg-config metadata resolves transitive requirements. The pinned ai-glib revision includes Codex, Claude Code, Grok Build, Cursor and Antigravity CLI classes.

=DEPS=bundled= is the default and builds pinned ai-glib/yaml-glib and links their static archives plus ai-glib's bundled mcp-glib archive. Also provide Fedora =libxml2-devel= and =libdex-devel= for ai-glib. Initialize nested git submodules before building:

#+begin_src bash
git submodule update --init --recursive
make -j4 DEPS=bundled
make tests DEPS=bundled
#+end_src

Both modes use the same source/API. =htmx-glib= and =orm-glib= are retained as pinned generation-integration dependencies; neither is a mandatory builder link. A generated site's README must list its own stack-specific packages, such as =sqlite-devel= for the example application.

For Immutablue/Hyacinth Macaw, add missing packages to the OS image build. Do not attempt a host =dnf install= or create a writable =/usr= overlay as an automatic build step.

* Build variants

#+begin_src bash
make -j4
make DEBUG=1 -j4
make DEBUG=1 ASAN=1 UBSAN=1 tests
make clean all tests -j4
bash tests/verify.sh
bash tests/install.sh
#+end_src

Release files live under =build/release/=; debug files under =build/debug/=. =clean= removes only the selected build type and leaves dependencies alone. Switching sanitizer flags rebuilds affected objects even within the same output directory. Upstream dependencies retain their own build policy; the project verification checks combined build output for warnings as well as nonzero status.

* Install

#+begin_src bash
make install PREFIX="$HOME/.local"
# Or inspect a staged installation without changing the host:
make install DESTDIR=/tmp/libresite-stage PREFIX=/usr
#+end_src

Install writes the CLI, shared/static libraries, public headers preserving their subdirectories, pkg-config metadata, recipes, docs, skills, license, prompt catalog and design snapshots. The CLI uses libresite's static archive, so it does not require locating the libresite shared library at startup. System mode still requires installed ai-glib/yaml-glib runtime libraries. Bundled mode links those dependencies into the resulting CLI/shared library. The public static archive contains libresite objects; static consumers resolve dependencies using the pkg-config private requirements or the same bundled archive group.

The shared library SONAME is =liblibresite-1.0.so.0= and the linker name is =liblibresite-1.0.so=. Embedding applications can use =pkg-config --cflags --libs libresite-1.0=. Ensure a nonstandard shared library prefix is discoverable by the normal loader configuration or a process-local =LD_LIBRARY_PATH= when testing.

Headers contain gtk-doc/GObject Introspection-compatible ownership comments. This release does not generate or install GIR/typelib files; embedding is through the C API.
