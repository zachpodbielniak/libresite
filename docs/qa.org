* Boundary

Native =validate= stays an in-process literal check: required non-whitespace text (or nonempty binary bytes), exact =contains=/=excludes= strings and inclusive byte bounds. It never parses HTML, never audits accessibility or SEO semantics, and never compiles or executes generated code.

=libresite --qa DIR= is a separate runner that consumes a *published* tree. It does not read checkpoints, does not call a provider, and does not run =tests/check.sh= or any generated program. Use it after generation, or on any directory that looks like an exported site.

#+begin_src bash
libresite --qa ./my-site
#+end_src

Library callers use =ls_qa_check()=. A readable tree with no structural findings returns true and a report. Import failures (symlinks, special files, empty directories) are errors. Findings are not errors: the function returns false and still fills the report. The CLI prints that report on stdout.

A successful report looks like:

#+begin_example
QA ./my-site
files: 12 (2 binary, 8 html)
OK structural checks; this is not an a11y, SEO, compile or browser audit
#+end_example

Each finding is a =FAIL= line naming the artifact and defect, followed by a finding count. HTML token search is ASCII case-insensitive. =javascript:= URLs are treated as external and ignored, same as =http(s)=, =mailto=, =tel=, =data= and fragments. Query strings and fragments are stripped before resolving relative targets. Root-relative paths are resolved from the project root. Traversal that escapes the tree is a finding.

* What it checks

- Regular files only, using the same import exclusions as revision (=.git=, =.libresite=, =*.libresite-work=)
- HTML documents: =<!doctype html=, =lang=, =<title=, viewport meta, charset
- Local =href=/=src= targets on common tags, plus =url()= in CSS and =og:image= content when present
- Binary assets (PNG, fonts, ICO and similar) are counted and must exist when referenced
- Missing HTML documents are a finding

External =http(s)=, =mailto=, =tel=, =data= and fragment-only references are ignored. Relative paths that escape the project are findings.

* What it does not check

HTML validity beyond those tokens, WCAG/ARIA conformance, ranking SEO, TypeScript/C compilation, HTTP, or browser rendering. Those belong to the generated project's own tests and a human pass. Native validate remains the recipe-time acceptance gate.

A successful QA report always states that it is not an a11y, SEO, compile or browser audit.

* Screenshots for review

=scripts/screenshots.sh SITE-DIR OUT-DIR [PORT]= serves a published site on 127.0.0.1 and saves phone (390x844) and desktop (1440x1000) screenshots of every top-level page with headless Firefox (=firefox=, =python3=). It is an operator tool for a person's review, like opening the site in a browser; the builder never runs it, and it judges nothing by itself. Lazily loaded images below the first screen may appear blank in a screenshot.
